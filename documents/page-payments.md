# $ralph + OMX

คุณคือ Senior Fullstack Engineer สำหรับโปรเจกต์ Autocar Service Center

Stack:
- Next.js App Router
- React
- TypeScript
- Tabler UI
- SweetAlert2
- Next.js API Routes
- Zod
- PostgreSQL
- Prisma
- NextAuth.js

Goal:
ปรับปรุงระบบหน้าชำระเงิน (Cashier Module) โดยแยกหน้าจอระหว่าง "รายการรอชำระ" (Pending Dashboard) และ "ฟอร์มรับชำระ" (Payment Terminal) เพื่อให้ตรงกับ Mockup และเพิ่มฟีเจอร์การชำระเงินผ่าน PromptPay QR และบัตรเครดิต (EDC / Online Gateway)

Workflow & UI Mappings:
1. **แยกหน้าจอ (Page Separation)**
   - **`/cash/pending` (Dashboard รายการรอชำระ):**
     - มีการ์ดสรุปยอดด้านบน (จำนวนบิลรอชำระ, ยอดรอชำระรวม)
     - แสดงตารางรายการงานที่มีสถานะ `WAITING_PAYMENT`
     - ปุ่ม "รับชำระ" จะ Redirect ไปที่ `/cash/payment?jobId=[id]`
   - **`/cash/payment` (Payment Terminal):**
     - ใช้ Layout แบบ 7:5 (ฝั่งซ้าย: ข้อมูลลูกค้า/บิล 7 ส่วน, ฝั่งขวา: ฟอร์มชำระเงินและสรุปยอด 5 ส่วน)

2. **ระบบชำระเงิน 3 รูปแบบ (Payment Methods)**
   - **เงินสด (Cash):**
     - ช่องกรอก "ยอดรับเงิน" 
     - ระบบคำนวณ "เงินทอน" ให้อัตโนมัติ (หากรับเงินน้อยกว่ายอดรวม จะไม่สามารถกดยืนยันได้)
   - **โอน/QR PromptPay (Transfer/QR):**
     - ใช้ตัวแปร `NEXT_PUBLIC_PROMPTPAY_ID` จาก `.env` (ตัวอย่าง: 0841013129)
     - ใช้ไลบรารี `promptpay-qr` เพื่อ Generate QR Code Payload ที่มียอดชำระแบบเจาะจง (`grandTotal`)
     - แสดง QR Code ด้วย `qrcode.react` เพื่อให้ลูกค้าสแกนจ่ายได้เลยโดยไม่ต้องกรอกตัวเลข
     - มี Switch "ยืนยันตรวจสอบยอดเงินเข้าบัญชีแล้ว" สำหรับแคชเชียร์ตรวจสอบก่อนปิดบิล
   - **บัตรเครดิต (Credit Card):**
     - แบ่ง Tab เป็น 2 โหมด:
       - *โหมดเครื่อง EDC:* กรอกประเภทบัตร (Visa/Mastercard) และเลข Reference No. จากสลิปเครื่องรูด
       - *โหมด Online Gateway:* จำลองการสร้าง Payment Link ยิงไปให้ลูกค้าทาง SMS เพื่อรอการอนุมัติ (รองรับการเชื่อมต่อ Omise/Stripe ในอนาคต)

3. **API Integration**
   - การยืนยันชำระเงิน จะส่ง HTTP POST ไปที่ `/api/cash/payment`
   - ระบบแนบ `paymentTypeId`, `reference` และรายละเอียดเพิ่มเติมไปในช่อง `notes` เพื่อใช้ในการออกใบเสร็จ (Receipt)

Step-by-Step Implementation:
1. ตั้งค่า `.env` เพิ่มตัวแปร `NEXT_PUBLIC_PROMPTPAY_ID=0841013129`
2. รันคำสั่ง `npm install promptpay-qr qrcode.react`
3. สร้างไฟล์ใหม่ `src/app/cash/pending/page.tsx` และย้าย Logic รายการงานซ้ายมือมาใส่ (แยก Dashboard)
4. รีแฟคเตอร์ไฟล์ `src/app/cash/payment/page.tsx` ให้เป็น Layout 7:5 ตาม Mockup 
5. สร้าง UI ส่วน Payment Methods ทั้ง เงินสด, QR PromptPay, และ บัตรเครดิต
6. เชื่อมต่อ State ผูก Logic การคำนวณเงินทอนและการสร้าง QR Code
7. ทดสอบการส่งข้อมูลไปยัง API `/api/cash/payment`

## 📌 คำอธิบาย Workflow Logic สำหรับหน้าระบบแคชเชียร์ (Cashier Module)

ระบบแคชเชียร์ถูกออกแบบมาให้ทำงานประสานกัน 2 หน้าจอหลัก เพื่อลดความสับสนและข้อผิดพลาดในการทำงานของพนักงานแคชเชียร์ โดยมีกระบวนการดังนี้:

### 1. หน้า Dashboard รอชำระ (`/cash/pending`)
หน้าจอนี้เปรียบเสมือน **"คิวงาน"** ของแคชเชียร์ โดยดึงข้อมูล Job ที่ผ่านการประเมินจากช่างหรือลูกค้าตกลงซ่อมเสร็จแล้ว (สถานะ `WAITING_PAYMENT`)
*   **เป้าหมาย:** แคชเชียร์สามารถมองเห็นภาพรวมว่าวันนี้มีคิวที่ต้องเก็บเงินกี่คัน รวมเป็นเงินเท่าไหร่
*   **Action:** เมื่อลูกค้าเดินมาที่เคาน์เตอร์ แคชเชียร์สามารถถามเลขทะเบียนรถ แล้วกดปุ่ม **"รับชำระ"** จากรายการนั้นๆ ได้เลย (ระบบจะพาไปหน้า `/cash/payment?jobId=...`)

### 2. หน้า Payment Terminal (`/cash/payment?jobId=...`)
เมื่อเข้ามาที่หน้านี้แล้ว แคชเชียร์จะต้องโฟกัสกับการปิดการขายและเก็บเงินกับลูกค้า "คนเดียว" เท่านั้น:
*   **การแสดงผล:** โชว์ข้อมูลลูกค้า, รถ, และรายละเอียดบิลทั้งหมดให้ลูกค้ายืนยันความถูกต้อง 
*   **การเลือกวิธีชำระเงิน:**
    *   **เงินสด (Happy Path):** เมื่อรับธนบัตรมา แคชเชียร์พิมพ์ตัวเลขที่รับมาลงไป ระบบจะคิดเงินทอนให้ทันที **ข้อควรระวัง:** หากกรอกตัวเลขน้อยกว่ายอดบิล ปุ่ม "ยืนยันรับชำระเงิน" จะถูกระงับไว้ ป้องกันความผิดพลาด
    *   **PromptPay QR (Digital Path):** เมื่อลูกค้าขอดู QR Code เพื่อแสกนจ่าย ระบบจะวาด QR Code ขึ้นมาบนหน้าจอแบบ Real-time โดยล็อคยอดเงินไว้ (ลดปัญหาลูกค้าพิมพ์เลขเงินตกหล่น) แคชเชียร์แค่ชี้ให้ลูกค้าสแกน เมื่อลูกค้าโอนเสร็จ แคชเชียร์เช็คสลิป แล้ว **สับสวิตช์ "ยืนยันเงินเข้า"** ถึงจะกดปิดบิลได้
    *   **เครื่องรูด EDC (Offline Credit):** กรณีลูกค้ายื่นบัตรเครดิตให้รูดกับเครื่อง EDC ของร้าน เมื่อรูดเสร็จ เครื่องพิมพ์สลิปออกมา แคชเชียร์ต้องหยิบเลข **Reference No.** จากสลิปมากรอกในระบบให้ตรงกัน เพื่อให้บัญชีตรวจสอบยอดกระทบยอดได้ภายหลัง
    *   **Online Gateway (Future Path):** ดูคำอธิบายเพิ่มเติมด้านล่าง

### 3. State Machine Transitions
*   เมื่อการชำระเงินทั้งหมดสมบูรณ์ และยิง API ไปที่ `/api/cash/payment`
*   ข้อมูลการชำระเงินจะถูกบันทึกลงฐานข้อมูล ระบบจะสร้างเลข **"ใบเสร็จรับเงิน" (Receipt)**
*   สถานะของ Job ใบนี้ จะเปลี่ยนจาก `WAITING_PAYMENT` ➜ `COMPLETED` โดยอัตโนมัติ
*   งานจะหายไปจากหน้า `/cash/pending` และเด้งไปอยู่คิวของพนักงานต้อนรับ เพื่อรอส่งมอบรถให้ลูกค้า (สถานะรอกด `DELIVERED`) ต่อไป

## 📌 หลักการทำงานของ Online Gateway (Stripe / Omise) และการนำไปใช้จริง

การทำงานแบบ **Online Gateway (ส่งลิงก์ให้ลูกค้าจ่ายเงินเองบนมือถือ)** เป็นฟีเจอร์สำหรับลูกค้าที่ไม่ได้อยู่ที่หน้าร้าน (เช่น เอารถมาทิ้งไว้แล้วรอให้ช่างไปส่ง) 

### ⚙️ หลักการทำงาน (Workflow)
กระบวนการนี้จะเกิดการเชื่อมต่อระหว่าง 4 ฝ่ายคือ: **ระบบแคชเชียร์ ➜ Payment Gateway ➜ ลูกค้า ➜ Webhook**

1. **แคชเชียร์กด "สร้างลิงก์ชำระเงิน":**
   ระบบหลังบ้าน (Next.js API) ของเราจะนำ **"รหัสบิล"** และ **"ยอดเงิน"** ส่งคำสั่งผ่าน API ไปยัง Payment Gateway (เช่น Omise)
2. **Gateway สร้าง Checkout URL:**
   Omise จะสร้างหน้าเว็บสำหรับรับบัตรเครดิตที่ปลอดภัย (Secure Checkout) ขึ้นมา 1 หน้า และตอบ URL กลับมาให้ระบบเรา (เช่น `https://pay.omise.co/link/abc123xyz`)
3. **ระบบเราส่ง SMS / LINE หาลูกค้า:**
   เมื่อเราได้ URL มา ระบบของเราจะส่งข้อความอัตโนมัติ (ผ่าน Thaibulksms หรือ LINE Messaging API) ไปที่เบอร์โทรศัพท์ของลูกค้า:
   > *"อู่ Autocar: แจ้งยอดชำระงานซ่อม กข-1234 จำนวน 6,256 บาท ชำระผ่านลิงก์นี้: https://pay... "*
4. **ลูกค้าจ่ายเงินบนมือถือ:**
   ลูกค้ากดลิงก์ เปิดหน้าเว็บของ Omise กรอกเลขบัตรเครดิตได้อย่างปลอดภัย (ข้อมูลบัตรจะไม่ผ่านเซิร์ฟเวอร์เรา ทำให้ปลอดภัย 100%)
5. **การทำงานของ Webhook (หัวใจสำคัญ):**
   เมื่อลูกค้ากดยืนยันจ่ายเงินสำเร็จ Omise จะยิงสัญญาณกลับมาที่เซิร์ฟเวอร์ของเราอัตโนมัติ (เรียกว่า Webhook) ไปที่ Endpoint URL ที่เราเตรียมไว้ (เช่น `/api/webhooks/omise`)
6. **ระบบของเราปิดบิลอัตโนมัติ:**
   เมื่อระบบเรารับ Webhook แจ้งว่า "จ่ายเงินสำเร็จ" หลังบ้านจะอัปเดตฐานข้อมูล (Prisma) เปลี่ยนสถานะบิลเป็น `COMPLETED` และหากแคชเชียร์เปิดหน้าเว็บทิ้งไว้ หน้าจอจะเด้งข้อความ "ลูกค้าชำระเงินเรียบร้อยแล้ว!" ทันที (ผ่าน WebSockets)

### 🚀 ตอนนำระบบไปใช้จริง ต้องทำอย่างไร?
หากต้องการเปิดใช้งานฟีเจอร์นี้ให้ใช้งานได้จริง นี่คือสิ่งที่ทีมต้องเตรียม:

1. **สมัครบริการ Payment Gateway (ฝั่งธุรกิจ):**
   จดทะเบียนเปิดบัญชีผู้รับเงินในนามนิติบุคคล (บริษัท) กับผู้ให้บริการ เช่น Opn Payments (Omise), Stripe, หรือ GB Prime Pay
2. **เอา API Keys มาตั้งค่า (ฝั่งโค้ด):**
   เมื่อสมัครผ่าน จะได้รหัส `Public Key` และ `Secret Key` ให้นำมาใส่ในไฟล์ `.env` ของโปรเจกต์
3. **พัฒนาระบบส่ง SMS หรือ LINE (ฝั่งโค้ด):**
   สมัครใช้บริการ SMS Gateway (เช่น SMSMKT) หรือสร้าง LINE Official Account (LINE OA) เพื่อเอา API Key มาทำระบบส่งข้อความอัตโนมัติ
4. **เขียนโค้ดรับ Webhook (ฝั่งโค้ด):**
   สร้างไฟล์ API Route ใหม่ เช่น `src/app/api/webhooks/omise/route.ts` เพื่อเปิดประตูหลังบ้านทิ้งไว้รอรับสัญญาณว่าจ่ายเงินผ่านแล้ว
5. **อัปโหลดขึ้น Server จริง:**
   Webhook จะทำงานไม่ได้หากโปรเจกต์ยังอยู่บนคอมพิวเตอร์ของคุณ (`localhost`) ระบบจะต้องถูกนำไป Host บนเซิร์ฟเวอร์จริง (เช่น Vercel, AWS) และมี Domain Name จริง เพื่อให้ Gateway ยิงข้อมูลกลับมาหาเราได้
